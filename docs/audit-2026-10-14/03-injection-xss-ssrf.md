## Sub-areas with NO findings

- **SQL injection — none.** `grep -rn "sql\.raw"` over `src/` returns zero hits. Every drizzle `sql` template interpolates via `${}` (parameterised), including the dynamic CTE builder at `src/app/api/v1/admin/donors/segments/route.ts:107-172`, where `sql.join(conditions, sql\` AND \`)` composes fragments rather than strings. `src/app/api/v1/search/route.ts:24` escapes LIKE metacharacters (`/[%_\\]/g`) before building the `ilike` pattern and bounds query length to 2–100 (`:16-21`). ORDER BY is never built from raw params: `admin/verification-queue/route.ts:43` indexes `campaigns[sortBy]` only after a zod enum parse (`:23-37`), and `admin/users/route.ts:52-53` uses a ternary over fixed columns. LIMIT/OFFSET go through `parsePagination`.
- **Anonymous-donor identity leakage — none.** Both public SELECTs that return donor fields pipe results through `redactAnonymousDonor` (`src/app/api/v1/campaigns/[slug]/donors/route.ts:55`; `src/app/api/v1/campaigns/[slug]/route.ts:66`), which forces `donorName:'Anonymous'` and `donorLocation:null` (`src/lib/api-helpers.ts:159-168`). Neither SELECT lists `donorEmail` at all; `donorEmail` appears only in admin routes, Stripe metadata, subscription lookups and the `count(distinct …)` aggregate in `stats/route.ts:13`. The OG route (`src/app/api/v1/og/campaign/[slug]/route.tsx:26-37`) selects campaign fields only — no donor data.
- **Email-template HTML injection — none.** `src/lib/email-templates.ts:15-22` defines `esc()` (5-char entity encode) and applies it to every interpolation inside `html:` bodies (31 `esc(p.campaignTitle)` occurrences there, 8 in `email-adaptive.ts`, where `name` is pre-escaped at `:175`/`:377`). The unescaped `${p.campaignTitle}`/`${name}` occurrences are **subject** lines (e.g. `email-templates.ts:60`, `email-adaptive.ts:181-187`), which are not HTML contexts. No user HTML (`storyHtml`/`bodyHtml`) is embedded in any template.
- **Sanitiser allowlist — sound; 18/18 payloads neutralised.** `repro/sanitize-probe.mts` imports the real `sanitizeHtml` from `src/lib/utils/sanitize.ts`. `<script>`, `<svg onload>`, `<iframe>`, `<form>`, `<meta http-equiv=refresh>` are dropped entirely; `on*` handlers stripped from `img`/`span`; `javascript:`, `JaVaScRiPt:`, entity-encoded `java&#115;cript:` and `data:text/html` all removed from `href`; `style` and `srcset` stripped. No `style`, `iframe`, `svg`, `on*` or `data:` permission exists in the allowlist (`:3-28`), and `allowedSchemesByTag` pins `img` to http/https. Residual nits are F-09.
- **Write-time vs read-time sanitising — both present; read-time is the load-bearing one.** All 9 API write paths sanitise on write (`api/v1/campaigns/route.ts:130`, `campaigns/[slug]/route.ts:142`, `user-campaigns/route.ts:144`, `user-campaigns/[id]/route.ts:158`, `.../updates/route.ts:70`, `.../impact-update/route.ts:205`, `admin/blog/route.ts:128`, `admin/blog/[id]/route.ts:114`, `admin/campaigns/[campaignId]/updates/route.ts:120`). Independently, **every** DOM sink that receives stored HTML re-sanitises at read time with the server-side `sanitize-html` (`src/app/campaigns/[slug]/page.tsx:261`; `components/campaign/CampaignUpdates.tsx:66`; `components/campaign/ImpactUpdate.tsx:70`; `components/admin/CampaignDetail.tsx:461`; `components/blog/ArticleRenderer.tsx:8`; `components/dashboard/CampaignUpdatesClient.tsx:149`; `app/dashboard/updates/page.tsx:89`; previews at `BlogEditor.tsx:77`, `CampaignEditor.tsx:138`). This is why F-06 (unsanitised cron writes) is Low rather than High: pre-existing dirty rows are cleaned on render. The remaining 19 `dangerouslySetInnerHTML` sites are `JSON.stringify(<server-built JSON-LD object>)`, not user HTML. `dompurify` is imported exactly once, at F-05.
- **Path traversal in object keys — none.** See F-07 evidence: UUID filenames, character-class-stripped folder and extension, `campaignId`/`userId` from validated params or the session.
